## 1. Умножение матриц: `mul_ijk` и `mul_ikj` (`-O2`)

При размере буфера `MAXN = 768` одна строка матрицы из чисел `double` (по $8$ байт) занимает в памяти $768 \times 8 = 6144$ байта. Полные листинги находятся в [`matmul_x86_O2.s`](matmul_x86_O2.s) и [`matmul_riscv_O2.s`](matmul_riscv_O2.s).

### Внутренние циклы в ассемблере

#### `mul_ijk` (внутренний цикл по `k`)
* **x86-64 (`-O2 -masm=intel`, $7$ инструкций в теле цикла `.L4`):**
  ```x86asm
  .L4:
      movsd   xmm0, QWORD PTR [rdx]   ; загрузить a[i][k] (подряд по строке)
      mulsd   xmm0, QWORD PTR [rax]   ; умножить на b[k][j] (элемент из столбца)
      add     rax, 6144               ; шаг по матрице b: +6144 Б (прыжок через строку!)
      add     rdx, 8                  ; шаг по матрице a: +8 Б (соседний элемент)
      addsd   xmm1, xmm0              ; накопить сумму s += a[i][k] * b[k][j]
      cmp     rdx, rcx                ; проверка конца строки
      jne     .L4
  ; После цикла: movsd QWORD PTR [rdi], xmm1 (однократная запись в c[i][j])
  ```
* **RISC-V 64-bit (`-O2 -march=rv64gc`, $6$ инструкций в теле цикла `.L4`):**
  ```asm
  .L4:
      fld     fa3, 0(a4)              # загрузить a[i][k]
      fld     fa4, 0(a5)              # загрузить b[k][j]
      add     a5, a5, a2              # шаг по b: +6144 Б (a2 = 8192 - 2048)
      addi    a4, a4, 8               # шаг по a: +8 Б
      fmadd.d fa5, fa3, fa4, fa5      # слитное умножение-сложение s += a[i][k] * b[k][j]
      bne     a5, a3, .L4
  # После цикла: fsd fa5, 0(a0) (однократная запись в c[i][j])
  ```

#### `mul_ikj` (внутренний цикл по `j`)
* **x86-64 (`-O2 -masm=intel`, $7$ инструкций в теле цикла `.L16`):**
  ```x86asm
      movsd   xmm1, QWORD PTR [rdi]           ; до цикла: загрузить a[i][k] в регистр
  .L16:
      movsd   xmm0, QWORD PTR b[rcx+rax]      ; читать b[k][j] подряд (+8 Б)
      mulsd   xmm0, xmm1                      ; b[k][j] * a[i][k]
      addsd   xmm0, QWORD PTR c[rax+rdx]      ; прибавить c[i][j] из памяти (+8 Б)
      movsd   QWORD PTR c[rdx+rax], xmm0      ; записать обновлённый c[i][j]
      add     rax, 8                          ; сдвиг индекса на следующий элемент (+8 Б)
      cmp     rsi, rax
      jne     .L16
  ```
* **RISC-V 64-bit (`-O2 -march=rv64gc`, $7$ инструкций в теле цикла `.L12`):**
  ```asm
      fld     fa3, 0(a1)                      # до цикла: загрузить a[i][k] в регистр
  .L12:
      fld     fa4, 0(a5)                      # читать c[i][j] подряд (+8 Б)
      fld     fa5, 0(a4)                      # читать b[k][j] подряд (+8 Б)
      addi    a5, a5, 8                       # сдвиг указателя c (+8 Б)
      addi    a4, a4, 8                       # сдвиг указателя b (+8 Б)
      fmadd.d fa5, fa5, fa3, fa4              # c[i][j] + b[k][j] * a[i][k]
      fsd     fa5, -8(a5)                     # записать новый c[i][j] в память
      bne     a5, a3, .L12
  ```

### Ответы на вопросы (Часть 1)
1. **Какие инструкции загружают и записывают элементы `a`, `b` и `c`:**
   * В **x86-64** используется инструкция `movsd` (а также прямое чтение операнда из памяти внутри арифметических команд `mulsd` и `addsd` благодаря CISC-архитектуре).
   * В **RISC-V** (строгая Load/Store архитектура) загрузка из памяти выполняется только командой `fld`, а запись в память — командой `fsd`.
2. **Как меняется адрес `b[k][j]` в `ijk`:** меняется **с шагом в целую строку ($6144$ байта)** на каждой итерации (`add rax, 6144` на x86-64; `add a5, a5, a2` на RISC-V, где константа $6144$ собрана двумя командами `li a2, 8192` и `addi a2, a2, -2048`), тогда как `c[i][j]` записывается один раз после внутреннего цикла.
3. **Что происходит с `b[k][j]` и `c[i][j]` в `ikj`:** оба массива читаются и обновляются **строго подряд по одной строке с шагом $+8$ байт** (прыжков на $6144$ байта нет), а элемент `a[i][k]` загружается в регистр один раз перед внутренним циклом.
4. **Сколько инструкций в теле внутреннего цикла (`-O2`):**
   * `mul_ijk`: **$7$ инструкций** на x86-64 против **$6$ инструкций** на RISC-V (в RISC-V команда `fmadd.d` объединяет умножение и сложение, а `bne` объединяет сравнение и переход).
   * `mul_ikj`: **$7$ инструкций** на x86-64 и **$7$ инструкций** на RISC-V.
5. **Появились ли векторные инструкции на `-O3 -march=native`:**
   * На **x86-64** появляются $256$-битные векторные инструкции AVX2 + FMA (`vbroadcastsd`, `vmovapd`, `vfmadd213pd` / `vfmadd231pd` с регистрами `ymm`).
   * На **RISC-V** при целевом профиле `-march=rv64gc` векторных инструкций нет; при включении векторного расширения `-march=rv64gcv` появляются инструкции RVV (`vsetvli`, `vle64.v`, `vfmacc.vf`, `vse64.v`).
6. **Почему `ikj` обходит память лучше при том же числе операций:** процессор загружает данные из RAM в кэш L1 кэш-линиями по **$64$ байта** ($8$ чисел `double` подряд). В `ikj` используются все $8$ чисел из каждой загруженной кэш-линии (пространственная локальность), а в `ijk` прыжок через строку на $6144$ байта приводит к промаху кэша на каждой итерации.

## 2. Алгоритм Штрассена: рекурсия в ассемблере (`-O2`)

Полные листинги функций `strassen` и `strassen_rec` из [`strassen_asm.c`](strassen_asm.c) сохранены в [`strassen_x86_O2.s`](strassen_x86_O2.s) и [`strassen_riscv_O2.s`](strassen_riscv_O2.s).

| Элемент | x86-64 (`-O2 -masm=intel`) | RISC-V 64-bit (`-O2 -march=rv64gc`) |
| :--- | :--- | :--- |
| **Пролог `strassen_rec`** | Сохраняет $6$ *callee-saved* регистров (`r15, r14, r13, r12, rbp, rbx` $= 48$ Б) и вычитает `sub rsp, 232` $= \mathbf{280\text{ байт}}$ ($+ 8$ Б адрес возврата $= \mathbf{288\text{ байт}}$, кратно $16$). | Отрезает `addi sp, sp, -304` $= \mathbf{304\text{ байта}}$ (кратно $16$), сохраняет `ra` (`296(sp)`) и $12$ регистров `s0..s11` (использует *shrink-wrapping*: сначала сохраняет `ra, s1, s2`, а остальные $10$ — только при `sz > 64`). |
| **Эпилог `strassen_rec`** | `add rsp, 232`, $6$ команд `pop`, `ret` (метка `.L1`). | `ld s0..s11, ra`, `addi sp, sp, 304`, `jr ra` (метки `.L1` / `.L58`). |
| **Передача $8$ аргументов** | $6$ аргументов в регистрах (`edi..r9`), $7$-й и $8$-й (`sc` и `work`) передаются через стек (`push` перед `call` и `pop` после). | Все $8$ аргументов передаются в регистрах **`a0..a7`** без использования стека. |
| **Рекурсивные вызовы** | **$7$ вызовов** `call strassen_rec` (для $M_1 \dots M_7$). Функции `add_mat` и `sub_mat` встроены (*inlined*). | **$7$ вызовов** `call strassen_rec` (псевдоинструкция для пары `auipc` + `jalr` / `jal`). |
| **Вызовы `malloc` / `free`** | Внутри `strassen_rec` — **$0$** (буфер `work` делится смещениями). В `strassen` — $1$ `call malloc` и хвостовой `jmp free` (плюс $3$ `calloc` + $3$ `free` при дополнении нулями). | Внутри `strassen_rec` — **$0$**. В `strassen` — $1$ `call malloc` и хвостовой `tail free` (плюс $3$ `calloc` + $3$ `free` при дополнении нулями). |
| **Базовый случай (`sz <= 64`)** | `cmp r10d, 64` $\to$ `jle .L59`: встроенный `base_mul` (обнуление через `rep stosq` + цикл `ikj`). | `li a0, 64` $\to$ `ble s2, a0, .L61`: встроенный `base_mul` (обнуление через `memset` + цикл `ikj`). |

### Ответы на вопросы (Часть 2)
* **Почему на маленьких матрицах Штрассен может проигрывать:** уменьшение числа блочных умножений с $8$ до $7$ требует **$18$ дополнительных матричных сложений и вычитаний** (`T1`, `T2`, `M1..M7`), сборки $4$ квадрантов `C11..C22` и $7$ рекурсивных вызовов. На малых размерах ($n \le 64$) время на чтение и запись промежуточных буферов и обслуживание рекурсии превышает экономию от одного умножения.
* **Что в ассемблере соответствует накладным расходам рекурсии:** создание и очистка стекового кадра ($280$ / $304$ байта), массовое перекладывание регистров в стек (*spilling*) вокруг $7$ вызовов `call strassen_rec`, $18$ отдельных циклов сложения/вычитания в памяти (`.L10`–`.L38`) и выделение кучи (`malloc` / `free`).

## 3. Сравнение двух ISA: `max2` и `max3` (`-O2`)

Исходный код [`max.c`](max.c) и листинги [`max_x86_O2.s`](max_x86_O2.s), [`max_riscv_O2.s`](max_riscv_O2.s):

```c
int max2(int a, int b) {
    return a > b ? a : b;
}

int max3(int a, int b, int c) {
    int m = a > b ? a : b;
    return m > c ? m : c;
}
```

### Листинги `max3` (`-O2`)
* **x86-64 (`-O2 -masm=intel`):**
  ```x86asm
  max3:
      cmp     edi, edx        ; сравниваем a и c
      mov     eax, esi        ; результат = b
      cmovl   edi, edx        ; если a < c, edi = c
      cmp     edi, esi        ; сравниваем max(a, c) и b
      cmovge  eax, edi        ; если max(a, c) >= b, eax = max(a, c)
      ret
  ```
* **RISC-V 64-bit (`-O2 -march=rv64gc`):**
  ```asm
  max3:
      mv      a5, a0
      sext.w  a0, a0          # знаковое расширение 32-битного int до 64 бит
      bge     a5, a2, .L5     # условный переход, если a >= c
      sext.w  a0, a2
  .L5:
      sext.w  a5, a0
      bge     a5, a1, .L6     # условный переход, если max(a, c) >= b
      sext.w  a0, a1
  .L6:
      ret
  ```

### Сравнительная таблица

| Критерий | x86-64 (`-O2`) | RISC-V 64-bit (`-O2 -march=rv64gc`) |
| :--- | :--- | :--- |
| **Аргументы и результат** | Аргументы: `edi`, `esi`, `edx`; результат: `eax`. | Аргументы: `a0`, `a1`, `a2`; результат: `a0`. |
| **Переход vs `cmov`** | **Без условных переходов:** используются инструкции условной пересылки `cmovl` и `cmovge`, что защищает конвейер от промахов предсказателя ветвлений. | **С условными переходами:** в базовом профиле `rv64gc` нет инструкции `cmov`, поэтому компилятор ставит $2$ перехода `bge` и инструкции `sext.w` (расширение $32$-битного `int` до $64$ бит по требованиям ABI). |
| **Размер `max3`** | **$6$ инструкций** ($5$ без учёта `ret`). | **$8$ инструкций** ($7$ без учёта `ret`). |

## 4. Чтение цикла: `sum` (`-O2`)

Исходный код [`sum_f.c`](sum_f.c) и листинги [`sum_f_x86_O2.s`](sum_f_x86_O2.s), [`sum_f_riscv_O2.s`](sum_f_riscv_O2.s):

```c
long sum(const long *a, long n) {
    long s = 0;
    for (long i = 0; i < n; i++)
        s += a[i];
    return s;
}
```

* **RISC-V (`-O2 -march=rv64gc`):**
  ```asm
  sum:
      ble     a1, zero, .L4   # защитная проверка n <= 0 ДО цикла
      slli    a1, a1, 3       # n * 8 байт
      mv      a5, a0          # текущий указатель ptr = a
      add     a3, a0, a1      # конечный адрес end = a + n * 8
      li      a0, 0           # s = 0
  .L3:
      ld      a4, 0(a5)       # загрузка a[i] (64 бита)
      addi    a5, a5, 8       # сдвиг указателя на следующий элемент (+8 Б)
      add     a0, a0, a4      # s += a[i]
      bne     a5, a3, .L3     # проверка условия в конце и переход назад
      ret
  .L4:
      li      a0, 0
      ret
  ```
* **Разбор:** стекового пролога и сохранения `ra` нет (функция листовая, все переменные в регистрах). Компилятор применил **инверсию цикла** (*Loop Inversion*):
  1. Проверка $n \le 0$ (`ble a1, zero, .L4`) поставлена **до цикла**, так как перевёрнутый цикл выполняется минимум один раз и при пустом/отрицательном $n$ нельзя обращаться к `a[0]`.
  2. Проверка продолжения поставлена **в конце тела цикла** (`bne a5, a3, .L3`), что сокращает число инструкций перехода на каждой итерации с двух до одного и улучшает работу аппаратного предсказателя ветвлений.

## 5. Чтение функции целиком: `f` (`-O2` и `-O0`)

```c
long f(long n) {
    long s = 0;
    for (long i = 0; i < n; i++) s += i * i;
    return s;
}
```

* **Сборка с `-O2` (RISC-V, файл [`sum_f_riscv_O2.s`](sum_f_riscv_O2.s)):**
  ```asm
  f:
      mv      a3, a0
      ble     a0, zero, .L4   # проверка n <= 0
      li      a5, 0           # i = 0
      li      a0, 0           # s = 0
  .L3:
      mul     a4, a5, a5      # i * i
      addi    a5, a5, 1       # i++
      add     a0, a0, a4      # s += i * i
      bne     a3, a5, .L3     # проверка i != n в конце цикла
      ret
  .L4:
      li      a0, 0
      ret
  ```
* **Пролог, сохранение `ra`, эпилог и `ret`:**
  * При **`-O2`** стековый кадр не создаётся (**$0$ байт**), так как все переменные размещены в регистрах. Регистр **`ra` не сохраняется**, потому что `f` — листовая функция (не вызывает другие функции и не затирает адрес возврата). Выход выполняется инструкцией `ret`.
  * При **`-O0`** (без оптимизаций) в RISC-V пролог выделяет кадр **`addi sp, sp, -48`** (**$48$ байт** на стеке) и сохраняет указатель кадра `sd s0, 40(sp)` (`ra` по-прежнему не сохраняется ввиду листового характера функции), а эпилог восстанавливает `ld s0, 40(sp)`, `addi sp, sp, 48` и завершается `jr ra` (`ret`).
* **Почему размер кадра стека кратен $16$:** стандарты вызова функций (**RISC-V LP64D ABI** и **System V AMD64 ABI**) требуют выравнивания указателя стека `sp` / `rsp` по границе **$16$ байт** для корректной работы $128$-битных типов и векторных регистров (в x86-64 невыровненные векторные инструкции вызывают аппаратное исключение), атомарных операций и предотвращения пересечения границ $64$-байтных кэш-линий.
